# 🍞 Toast 요구사항

> 오른쪽 아래 또는 상단에 나타나는 토스트 컴포넌트의 기능 / 비기능 요구사항

---

## ⚙️ 기능 요구사항

각 항목은 "무엇을 결정해야 하는가"가 아니라 **결정된 정책**으로 기술한다.

| # | 결정해야 할 것 | 정책 | 근거 |
|:-:|------|------|------|
| 1 | 토스트 위치 | 사용자 액션 결과는 `bottom-right`, 세션 만료 · 네트워크 끊김 같은 전역 시스템 알림은 `top-right` | 액션 결과는 조작 지점 근처에서, 시스템 알림은 시선이 먼저 닿는 상단에서 인지시킨다 |
| 2 | 등장까지의 시간 | 이벤트 발생 후 **100ms 이내** 표시, 진입 애니메이션 **150ms** | 100ms를 넘으면 사용자가 자신의 액션과 피드백을 연결하지 못한다 |
| 3 | 유지 시간 | `success` · `info` **3초**<br>`warning` **5초**<br>`error` 자동 닫힘 없음 (수동 닫기)<br>`loading` 자동 닫힘 없음 (결과로 전환) | 읽고 넘겨도 되는 정보와 반드시 인지해야 하는 정보를 구분한다 |
| 4 | 퇴장까지의 시간 | 퇴장 애니메이션 **120ms** | 진입보다 짧게 두어 잔상이 남지 않게 한다 |
| 5 | 퇴장 방향 | 등장 방향의 역방향 (`top-right` → 위로, `bottom-right` → 아래로) | 등장/퇴장 경로가 일치해야 공간 모델이 유지된다 |
| 6 | 최대 노출 개수 | 화면 동시 노출 **3개**, 대기 큐 **최대 20개** | 4개 이상은 읽히지 않고 화면만 가린다 |
| 7 | 사용자 강제 닫기 | `error` · `warning` · `loading` 은 **항상** 닫기 버튼 노출<br>`success` · `info` 는 옵션 | 자동으로 사라지지 않는 토스트는 닫을 수단이 반드시 있어야 한다 |
| 8 | 중복 처리 | 동일 `dedupeKey` 가 이미 떠 있으면 새로 만들지 않고 기존 토스트를 갱신 | 네트워크 오류 10회에 토스트 10개가 쌓이는 것을 막는다 |
| 9 | 라우트 변경 | 라우트가 바뀌면 `success` · `info` 는 즉시 닫고, `error` · `loading` 은 유지 | 페이지에 종속된 가벼운 피드백만 정리한다 |

## 🎨 비기능 요구사항

| # | 항목 | 정책 |
|:-:|------|------|
| 1 | **접근성** | `success`/`info` → `role="status"` + `aria-live="polite"`<br>`error`/`warning` → `role="alert"` + `aria-live="assertive"`<br>live region 컨테이너는 **앱 마운트 시점에 빈 채로 DOM에 존재**시키고 텍스트만 삽입<br>닫기 버튼 · 액션 버튼은 키보드로 도달 가능해야 한다 |
| 2 | **타이밍 제어** | hover · focus 중에는 자동 닫힘 타이머를 일시정지한다 (WCAG 2.2.1 Timing Adjustable)<br>액션 버튼이 있는 토스트가 클릭 전에 사라지면 안 된다 |
| 3 | **모션** | `prefers-reduced-motion: reduce` 인 경우 이동 애니메이션을 제거하고 `opacity` 전환만 사용한다 |
| 4 | **성능** | 레이아웃을 재계산하는 속성 대신 `transform` · `opacity` 만 사용<br>`will-change` 는 애니메이션 구간에만 한시적으로 부여 |
| 5 | **렌더링 격리** | `Portal` 로 `document.body` 하위에 렌더링하여 부모의 stacking context 영향을 받지 않는다 |
| 6 | **토스트 종류** | 사용자가 취해야 할 행동의 강도를 기준으로 `success` · `error` · `warning` · `info` · `loading` 5종으로 나눈다 |
| 7 | **관측 가능성** | 노출 · 닫힘(사유 포함) · 중복 억제를 이벤트로 남긴다 |
