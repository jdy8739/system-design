# 🏗️ Architecture

> 토스트 모듈의 디렉토리 구조와 설계 방향

---

## 📁 디렉토리 구조

```
toast
 └── src
      ├── components   → 컴포넌트 ui (ToastContainer, ToastItem, ToastIcon, CloseButton)
      ├── libs         → 토스트 도메인 로직 (store, queue, api, timer)
      └── utils        → 도메인과 무관한 순수 함수 (dedupe, priority)
```

| 레이어 | 책임 | React 의존 |
|--------|------|:---:|
| `components` | 렌더링, 애니메이션, 접근성 속성 부여 | ✅ |
| `libs` | 큐 관리, 중복 제거, 타이머, 공개 API | ❌ |
| `utils` | 입력 → 출력만 있는 순수 함수 | ❌ |

`libs` 를 React 밖에 두는 이유는 토스트가 컴포넌트 내부뿐 아니라 **axios 인터셉터, mutation 콜백처럼 React 트리 밖에서도 호출**되기 때문이다.
컴포넌트는 store 를 구독만 하고, 상태의 소유권은 `libs` 가 갖는다.

```
openToast()  →  libs/store  →  구독  →  ToastContainer (Portal)  →  ToastItem[]
     ↑
  도메인 로직 / 인터셉터 / mutation 콜백
```

---

## 🚪 렌더링 위치

`ToastContainer` 는 컴포넌트 트리 안이 아니라 **Portal 로 `document.body` 하위에 렌더링**한다.

부모 요소에 `overflow: hidden`, `transform`, `filter`, `opacity` 중 하나라도 걸려 있으면 새로운 stacking context 가 생성되어 `z-index` 를 아무리 높여도 토스트가 그 안에 갇힌다.
Portal 은 이 문제를 구조적으로 제거한다.

## 🧭 토스트로 처리할 것과 아닌 것

토스트는 **모든 알림을 보여주는 도구가 아니라, UX 피드백의 한 종류**다.
판단 기준은 *"사용자가 이걸 놓쳐도 되는가"* 이다.

### ✅ 토스트가 적합한 경우 — 놓쳐도 되는 짧은 피드백

| 케이스 | 이유 |
|--------|------|
| 프로필 저장 성공 | 사용자가 방금 한 행동의 결과 확인 |
| 장바구니 담기 성공 | 화면 전환 없이 결과만 알리면 충분 |
| 파일 업로드 완료 | 완료 사실만 전달하면 됨 |
| 복사 완료 | 되돌릴 필요도, 후속 행동도 없음 |
| 자동 저장 실패 | 재시도가 자동으로 일어나며 치명적이지 않음 |

### ⚠️ 토스트만으로 부족한 경우 — 반드시 인지하고 행동해야 하는 문제

| 케이스 | 대신 필요한 것 |
|--------|----------------|
| 결제 실패 | 결제 화면 내 인라인 에러 + 재시도 동선 |
| 권한 없음 | 접근 차단 화면 또는 권한 요청 모달 |
| 세션 만료 | 재로그인 모달 (토스트는 보조) |
| 페이지 데이터 로딩 실패 | 화면 자체의 error state + 재시도 버튼 |
| 폼 유효성 오류 | 해당 필드 옆 인라인 메시지 |

> 사라지는 UI 에 사용자의 다음 행동을 의존시키면 안 된다.
> 3초 뒤에 없어질 곳에 "다시 시도하세요" 를 적는 순간 그 정보는 유실된다.

## 🧠 설계 원칙

### 서버 상태 기반 메시지

프로필 저장, 결제, 업로드처럼 서버 상태와 관련된 케이스는 서버가 내려주는 메시지를 그대로 토스트에 담는다.
단, 서버 메시지를 그대로 노출하기 곤란한 5xx 계열은 클라이언트가 정의한 공통 문구로 대체한다.

### 클라이언트 단독 오류

서버와 무관한 클라이언트 단독 오류(폼 입력값 오류 등)는 정적인 메시지를 주입한다.
다만 폼 필드 단위 오류는 위 표에 따라 **토스트가 아니라 인라인 메시지**로 처리한다.

### 호출 책임의 분리

어느 레이어에서 토스트를 띄울지는 [Interface](./Interface.md#-호출-책임-정책) 에서 정의한다.
전역 인터셉터에서 무차별적으로 띄우면 사용자가 유발하지 않은 알림이 뜨게 된다.
